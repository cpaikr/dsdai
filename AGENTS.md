# Repository instructions

## Scope

- This repository owns the `dsd` CLI for reading and surgically editing
  Korean DART Editor `.dsd` documents, and the `dart-dsd` agent skill that
  drives it. `crates/dsd` owns the format logic; `crates/dsd-cli` adapts it to
  the process contract, release checks, and upgrades. Keep `.dsd` semantics in
  the library.
- `skills/` is the published skill catalog, laid out like `../agent-scripts`:
  `skills/<name>/SKILL.md`, `agents/openai.yaml`, and directly linked
  resources. Repo-local `.agents/skills/` and `.claude/skills/` are generated by
  `sjskills` from `sjskills.toml`; never edit those copies.
- Observed format facts live in `skills/dart-dsd/references/format.md`, written
  in our own words and free of any sample's content.

## Read first

- `README.md` for commands, installation, and updates.
- `ARCHITECTURE.md` for boundaries, invariants, and the JSON process contract.
- `docs/release.md` before any release work.

## Confidentiality

- This repository is public. `fixtures/private/` holds real audit `.dsd` files
  and locally installed DART schemas; it is git-ignored and its contents, file
  names, sizes, and derived values must never be committed, quoted in docs,
  tests, or commit messages, or uploaded.
- Public tests and examples use only independently authored synthetic
  fixtures (`fixtures/public/`, built from `fixtures/public/sample/`).
- Do not copy DART XSD/DTD text or DART Editor form wording (insertion
  comments, library names) into the repository; describe behavior in our own
  words and use invented strings in fixtures.

## Working rules

- The process contract is a compatibility surface: one newline-terminated
  JSON envelope per invocation, stable `error.code` values, exit 0/1/2. Add
  fields additively; a breaking change needs a new `metadata.contract`.
- Never re-serialize XML or re-zip with a generic writer; edits splice byte
  ranges. A behavior change needs a test in `crates/dsd-cli/tests/cli.rs`
  against the public fixture or a variant of it.
- Treat an element as verified only after checking it on a real document;
  `OBSERVED_TAGS` and the format reference's coverage list must agree (a test
  enforces it).
- Keep the skill small: routing and universal rules in `SKILL.md`, task detail
  in its references, exact syntax in `dsd --help`. Keep `SKILL.md` frontmatter
  to `name` and `description`, link every reference directly from it, and
  keep bundled files inside the skill directory.

## Release

- Releases follow `docs/release.md`. `scripts/release-targets.json` is the
  only target inventory; `scripts/release.py` (standard library only)
  packages, certifies, and publishes. The workspace version in `Cargo.toml` is
  the version authority. Never push tags or dispatch Release as part of
  ordinary implementation work.

## Validation

- `python scripts/check.py` runs package checks, `cargo fmt`/`clippy`/`test`
  (tests with the test-only `fixture-origin` feature), the release tooling's
  unit tests, and a CLI smoke run over the public fixture and, when
  `fixtures/private/` exists, the private corpus without printing content.
- Run it after changing the CLI, the skill, fixtures, or release tooling.
